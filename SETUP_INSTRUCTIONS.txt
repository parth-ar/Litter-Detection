1. SYSTEM ARCHITECTURE & AUTONOMOUS OPERATION
================================================================================
The system is built for autonomous, unattended vehicle deployment on a
Raspberry Pi. It runs automatically upon vehicle ignition/boot:

1. BOOT SCAN & BASE LOCATION:
   - On boot, the system initializes sensors and scans for an active GNSS 3D fix
     for up to 15 seconds.
   - As soon as a 3D fix is acquired, it establishes that position as the base
     starting location.

2. 10-METER DISTANCE-BASED TRIGGER:
   - Using real-time geodesic calculations (Haversine formula), the vehicle's
     displacement from the base point is tracked.
   - Exactly every 10 meters travelled, the system flushes the camera buffer,
     captures a fresh frame, and executes the fine-tuned YOLO model.
   - If litter is detected, the frame is saved with the metadata banner, telemetry
     sidecar JSON is generated, and the Orange LED executes a triple blink.

3. 15-SECOND GNSS LOSS SCAN & 30-SECOND CLOCK FALLBACK:
   - If GNSS signal drops (tunnel, dense canopy, or disconnect), the system starts
     a 15-second grace scan window.
   - If GNSS fix is not regained within 15 seconds, the system seamlessly falls
     back to a clock-based trigger: clicking a frame every 30 seconds.
   - The background thread continues scanning for GNSS. As soon as a 3D fix is
     restored, that location becomes the new base anchor and the 10-meter distance
     loop resumes immediately.

2. HARDWARE CONNECTIONS & PI 40-PIN HEADER PINOUT
================================================================================

A. Orange Status LED Connection (BCM GPIO 25):
----------------------------------------------
Connect a single Orange LED to the Raspberry Pi 40-pin GPIO header:
- Anode   (+) (Long leg)  --> 220–330 Ohm resistor --> Physical Pin 22 (BCM GPIO 25)
- Cathode (-) (Short leg) --> Physical Pin 20 (GND)

Pi 40-Pin Header Diagram:
  Pin 1 (3.3V)           [ .  . ] Pin 2 (5V)
  Pin 3 (GPIO 2 / SDA)   [ .  . ] Pin 4 (5V)
  Pin 5 (GPIO 3 / SCL)   [ .  . ] Pin 6 (GND)
  ...
  Pin 19 (GPIO 10)       [ .  . ] Pin 20 (GND)       <-- Orange LED Cathode (-)
  Pin 21 (GPIO 9)        [ .  . ] Pin 22 (GPIO 25)   <-- Orange LED Anode (+) via 220 Ohm
  ...

B. DS3231 I2C Real-Time Clock (RTC):
------------------------------------
DS3231 Pin     Pi Physical Pin     Pi Function
----------     ---------------     -----------
VCC            Pin 1               3.3V Power
GND            Pin 6 (or 9, 14)    Ground
SDA            Pin 3               GPIO 2 (I2C1 SDA)
SCL            Pin 5               GPIO 3 (I2C1 SCL)

Enable I2C in Raspberry Pi OS:
  sudo raspi-config
  -> 'Interface Options' -> 'I2C' -> Enable -> Reboot.
Verify detection on address 0x68:
  sudo apt-get install -y i2c-tools
  sudo i2cdetect -y 1
  (You should see '68' or 'UU').

C. Camera Connection:
---------------------
- USB Webcam: Plug into any USB 3.0 port (blue port on Pi 4/5).
- Raspberry Pi Camera Module: Connect ribbon cable to CAM/CSI port.
Verify camera is recognized:
  ls -l /dev/video*   (default is /dev/video0)

3. ORANGE STATUS LED STATES & BEHAVIOR
================================================================================
A singular Orange LED on BCM GPIO 25 (Physical Pin 22) communicates all system
states without requiring an external display or monitor:

1. SOLID LIGHT:
   - System is fully functional, healthy, and operational.
   - Camera is streaming, GNSS 3D fix is locked, and 10m distance tracking is active.

2. CONSTANT BLINKING (1 Hz — 500ms ON / 500ms OFF):
   - Scanning for GNSS.
   - Indicates the system is searching for a 3D satellite fix (at bootup or during
     a reconnection grace period when signal is obstructed).

3. TRIPLE BLINK (3 Fast Pulses — 80ms ON / 80ms OFF):
   - Frame capture trigger.
   - Fires each time a frame is clicked from the camera (either at a 10m waypoint
     or at a 30s clock fallback interval), then returns to solid light.

4. HEARTBEAT BLINK (Double-Pulse Pulse-Pulse-Pause — 120ms ON, 120ms OFF, 120ms ON, 740ms OFF):
   - Error or hardware failure encountered.
   - Signals a fault condition (camera disconnected/failed to open, filesystem error,
     or critical uncaught exception).

4. NAVCAST PHONE GNSS SETUP (USB TETHERING)
================================================================================
The NavCast Android application acts as the vehicle GNSS receiver over USB:

1. Connect Phone to Raspberry Pi using a reliable USB data cable.
2. Enable USB Tethering on Phone:
   - Go to Android Settings -> Hotspot & Tethering -> Toggle 'USB Tethering' to ON.
   - The Pi will automatically create network interface 'usb0'.
3. Open NavCast App on Phone:
   - Grant 'High Accuracy' Location / GPS permissions.
   - Start NMEA TCP Server (default port: 10110).
4. Auto-Discovery:
   - 'NAVCAST_AUTO_DETECT = True' is enabled in config.py.
   - The Raspberry Pi automatically detects the phone's gateway IP address and
     connects to port 10110 seamlessly.

5. SOFTWARE INSTALLATION & ENVIRONMENT SETUP ON RASPBERRY PI
================================================================================

1. Update system packages:
   sudo apt-get update && sudo apt-get install -y git python3-pip python3-venv libgl1 libglib2.0-0

2. Clone or navigate to the repository:
   cd /home/pi/Solid-Waste/Litter-Detection-main/Litter-Detection-main

3. Create and activate a Python virtual environment:
   python3 -m venv .venv
   source .venv/bin/activate

4. Install dependencies:
   pip install --upgrade pip
   pip install -r requirements.txt

5. Grant user access to GPIO and video devices:
   sudo usermod -a -G gpio,video,i2c $USER

6. RUNNING AS A SYSTEMD BACKGROUND SERVICE ON BOOT
================================================================================
To configure the system to launch completely autonomously on vehicle boot:

1. Run the automated installer:
   cd /home/pi/Solid-Waste/Litter-Detection-main/Litter-Detection-main
   sudo bash install_service.sh

   What this does automatically:
   - Detects the exact workspace directory and Python virtualenv interpreter.
   - Generates and registers /etc/systemd/system/litter-detection.service.
   - Configures auto-restart (Restart=always, RestartSec=5s).
   - Enables the service to start automatically on every system boot.

2. Verify service status:
   sudo systemctl status litter-detection

3. Follow live real-time vehicle logs:
   sudo journalctl -u litter-detection -f

4. Stop, start, or restart service manually:
   sudo systemctl stop litter-detection
   sudo systemctl start litter-detection
   sudo systemctl restart litter-detection

5. Uninstall service (if needed):
   sudo bash uninstall_service.sh

7. CLI ARGUMENTS & MANUAL OPERATION MODES
================================================================================
If running manually from terminal:

A. Headless Service Mode (Same as Boot Mode):
   python litter_event_logger.py --headless

B. Interactive GUI Mode (with Live Telemetry Viewfinder):
   python litter_event_logger.py --show

C. Custom Distance or Fallback Intervals:
   python litter_event_logger.py --distance-interval 15.0 --gnss-timeout 15.0 --fallback-interval 30.0

D. Continuous Video Test Mode:
   python litter_event_logger.py --no-webcam --video "test vid/trash stock.webm" --trigger-mode continuous --show

Key CLI Options:
  --distance-interval METERS  : Geodesic distance between captures (default: 10.0m)
  --gnss-timeout SECONDS      : Grace period before falling back to clock (default: 15.0s)
  --fallback-interval SECONDS : Time between frames during clock fallback (default: 30.0s)
  --trigger-mode {auto,distance,clock,continuous} : Default is 'auto'
  --headless                  : Run without GUI (standard for boot service)
  --show                      : Viewfinder preview (spacebar / 'c' forces manual trigger)
  --save-all-triggers         : Save survey frames even if clean (0 detections)

8. OUTPUT FORMAT: NON-DESTRUCTIVE BANNER & TELEMETRY SIDECARS
================================================================================
All captured event frames land in: runs/EventLogger/

A. Image Files (Frame_{N}.jpg):
- The original camera image is 100% preserved with zero coverage.
- A 70-pixel black banner is appended strictly BELOW the frame (e.g. 640x480 -> 640x550).
- Banner styling matches exact reference:
  * Line 1: RTC: YYYY-MM-DDTHH:MM:SS (Bright Yellow)
  * Line 2: GNSS: <latitude:.8f>, <longitude:.8f> (Bright Green)
    (or 'GNSS: NO FIX (TIME TRIGGER)' in orange during clock fallback)
  * Developer name is completely omitted.

B. Telemetry Sidecars (Frame_{N}.json):
Saved alongside each image with full machine-readable telemetry:

9. TROUBLESHOOTING & FAQ
================================================================================
Q: Orange LED stays constantly blinking.
A: The system is scanning for GNSS. Ensure USB tethering is active on the phone and
   NavCast is streaming NMEA on port 10110. Once outdoors with a 3D fix, the LED turns solid ON.

Q: Orange LED is flashing in a heartbeat pattern (double-pulse).
A: An error has occurred. Run 'sudo journalctl -u litter-detection -e' to inspect the error.
   Common causes: camera cable loose or USB webcam disconnected.

Q: How do I test without moving the vehicle?
A: In GUI mode ('--show'), press the Spacebar or 'c' key in the viewfinder to manually
   force a trigger event, capture a frame, and test the Orange LED triple blink.
